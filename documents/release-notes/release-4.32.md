# Release 4.32

A maintenance release, and an important one: two of these fixes are conversions and form pages failing outright in busy or guest-facing orgs.

- **Two people submitting at the same moment no longer break each other's conversion** (#621): when two submissions were converting within a second or two of each other, one of them could stop dead with `Conversion Status = Error` and a log reading "Does not include input variable of type Form Submission Convert" against a flow that plainly does declare it. The message was simply wrong. Platform events published close together arrive together, and the dispatcher was looking up the flow's input variable once for the whole group, so only the first flow in the group was recognised and every other one was rejected. Each flow is now resolved on its own. **Nothing to reconfigure**; if you have seen this error on a campaign landing page or an event registration burst, those responses can be reprocessed and will now run.
- **Public form pages load again where a subscriber field shares a name with a retired packaged one** (#622): a guest opening a form could get a hard failure, `No such column ... on entity Form Submission`, naming a field the guest could actually read. It happened when your org has its own field, for example `Emergency_Contact_Phone__c`, whose name matches a packaged field that Flow Tool Kit shipped and later removed. The removed field stays in the org as **Installed Deleted**, and the query resolved to it rather than to yours. Admins never saw the failure, because they have access to both; only guests and community users did. The guard that was meant to catch this had a casing bug that stopped it ever matching. **Your field is now skipped rather than bound to the wrong one, so the page loads.** To get the field itself back into the form, erase the retired packaged field in Setup (Deleted Fields → Erase); a warning naming the field is written to the debug log so you can tell which one.
- **Conversions no longer loop when your conversion controller was cloned before 4.2** (#620): a submission would convert its Contact or Account successfully, the log would say so, the lookup would be stamped, and then the same rule would fire again on the next pass, ending in an Error once the loop guard stopped it at five attempts. Controllers cloned before 4.2 publish an event that does not carry the status field name, which newer packaged steps rely on, so nothing ever recorded the rule as finished. Those steps now work out the status field for themselves exactly as the retired formulas did, and where the name genuinely cannot be resolved they log a warning saying so instead of silently doing nothing. **Older overrides keep working as they are**, so there is no forced upgrade of your clone; re-cloning from the current packaged controller remains the tidier long-term option.
- **Sliders, steppers and preset amounts now trigger formula recalculation** (#626): with a number, currency or percent field rendered as a slider, a stepper or preset amount buttons, and **Trigger Formula Recalculations** switched on, the dependent formula came back blank instead of recalculating. Typing into a plain number input always worked. These controls send their value as a number rather than as text, and the recalculation refused it and quietly moved on. Both shapes are accepted now. **This matters on payment forms**, where the charged amount is calculated from the response, and a preset donation button previously left that calculation empty.
- **Read-only postal code respects its own field security** (#609): where an org has different field-level security across the parts of an address, the postal code box was locked or unlocked according to the **State/Province** field's permissions rather than its own. Only orgs with deliberately uneven address permissions were affected. The label shown for a postal code on a custom address field also said "State"; both come from the same copy-and-paste and both are fixed.
- **Fewer wasted field renders on large forms** (#608): every field rendered through an override, which includes numbers with steppers, rich text and file upload, was quietly rendering an extra hidden slot only picklist and checkbox fields ever needed, and each one carried the cost of wiring a record form field. Invisible, but it added up on long forms. Nothing changes visually.

Admins: load your public form pages, including any embedded form URLs, once after upgrading; the first visit pays the component compile so a real visitor does not.
